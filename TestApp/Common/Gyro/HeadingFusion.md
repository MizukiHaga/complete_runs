# 連続方位推定と車輪モデル校正

`HeadingFusionSettings.h` の `Enabled=true` が既定。
10ms周期の専用タスクで、直進・旋回・停止中を通して角度を更新し、残留ジャイロbiasは静止拘束が成立した間だけ学習する。
直進制御と旋回制御は、同じ `gGyro.heading()` の推定角を使用する。
追い旋回は追加しない。

## 従来との差

| 処理 | 従来 | 連続方位推定 |
|---|---|---|
| 車輪の角度換算 | 共通のEncoderPer90Deg | 左右有効径と有効トレッドを別々に指定 |
| 融合 | 旋回ごとに一定比率 | 角度＋残留biasの2状態KF |
| 更新 | 旋回中と停止後 | 専用タスクで直進・旋回・停止中も更新 |
| 旋回後 | 方位オフセットへTurnDrift補正を加算 | 追加補正なし。共通推定角をそのまま使用 |
| 不一致 | 常に同じ重み | 正規化残差に応じて車輪の観測分散を一時的に増加 |
| 観測源 | 直進1D・旋回3Dを切替 | ドライバで校正済みの1D角に統一 |

Enabled=falseで従来のTurnDriftへ戻して比較できる。
有効時は旧TurnDriftのestimate/updateと旋回後addHeadingCorrectionを呼ばず、二重適用しない。
setRateHeadingは既存呼出の互換性を維持するが、共通推定器の観測源は切り替えない。
resetは角度原点・車輪基準だけを取り直し、学習済みbiasを維持する。

## 車輪モデルの設定と校正

編集先は `HeadingFusionSettings.h`。
車輪角は前進正、車体角は右旋回(CW)正。角度の単位はdeg。

```text
エンコーダ差分角 = (DL × 左車輪差分角 − DR × 右車輪差分角) / (2 × B)
```

| 設定 | 初期値 | 意味 |
|---|---:|---|
| LeftWheelDiameterMm | 56 | 左の有効車輪径 |
| RightWheelDiameterMm | 56 | 右の有効車輪径 |
| EffectiveTrackMm | 112 | 接地・滑りの影響を含む有効トレッド |

**56/56/112は実測校正済みではなく、従来のEncoderPer90Deg=180と同じ換算の初期値。**
コードだけで床に対する真の移動量は測れないため、実測値を入力してから再ビルドする。
Nansho3のCoreStraightDeg・InitialStraightDeg等の距離設定は変更していない。
KYOKUの左右速度制御・XYオドメトリ用寸法も、このヘッダから自動変更しない。

校正手順の目安:

1. 実走と同じ床・荷重・タイヤ状態で、既知距離の直進、左右旋回、CW/CCW正方形走行を測る。
2. 開始・終了の位置と向きを床の基準線や上方カメラから測る。IMUを真値扱いしない。
3. 平均的な終了誤差と試行間のばらつきを分ける。平均の偏りは車輪モデル、ばらつきは滑り等を疑う。
4. 左右径差とトレッド誤差を同時に調整し、一方向だけで合ったと判断しない。
5. 低速で合わせた後、実走速度でも確認する。モデルに合わない横滑りは校正だけでは除けない。

背景: [UMBmarkの原著](https://web.cecs.pdx.edu/~mperkows/CLASS_479/S2006/Paper-correction-odometry-error.pdf)、
[方位誤差を用いる校正](https://journals.sagepub.com/doi/10.5772/50906)。

## 推定器の設定

| 設定 | 単位・初期値 | 調整の意味 |
|---|---|---|
| GyroNoiseDegPerRootSec | deg/√s、0.08 | 大きいほどジャイロ積分を不確かと扱う |
| BiasWalkDegPerSecPerRootSec | (deg/s)/√s、0.02 | 大きいほど残留biasの時間変化へ追従する |
| EncoderDeltaNoiseDeg | deg、0.15 | 量子化を含む車輪差分角の不確かさ |
| WheelRateNoiseDegPerSec | deg/s、2 | 通常走行中の車輪角速度誤差 |
| InitialBiasStdDegPerSec | deg/s、0.5 | 開始時の残留biasの不確かさ |
| InnovationLimit | 3 | この標準偏差倍率を超える残差で車輪分散を増やす |
| MaxWheelNoiseScale | 1000 | 車輪分散の増大倍率の上限 |
| StationaryEncoderRangeDeg | deg、2 | 停止確認開始からの各車輪の最大値−最小値の許容幅 |
| StationaryHoldSec | s、0.5 | 停止指令・IMU静止・車輪変動幅・角速度を連続確認する時間 |
| StationaryRateNoiseDegPerSec | deg/s、0.05 | 静止時の角度増分0という拘束の不確かさ |
| StationaryGyroLimitDegPerSec | deg/s、0.5 | 静止拘束を使用する角速度の範囲 |

まず寸法校正を行い、雑音設定は初期値のまま比較する。
偏りを減らすためにEncoderWeightを変更する方式ではなくなった。
走行中はbias値を固定し、車輪側の倍率・滑りの系統誤差をbiasへ学習しない。車輪誤差による角度更新への影響は残るため、寸法校正は必要。

IMUドライバ内の既存の静止校正は利用する。推定するbiasはその補正後の残留角速度であり、
既存のセンサbias値を再度差し引くわけではない。
停止指令・IMU静止・小さい角速度が続き、各車輪の変動幅が2deg以内で0.5秒経過すると、車輪差分観測を「実際の角度増分0」の拘束へ置き換える。
同じジャイロ値を、さらに独立なbias観測として二重には取り込まない。

## 低計算量の差分角KF

状態は[角度θ、残留角速度bias b]。予測は `θ += ジャイロ差分角 − b × dt`。
車輪の差分角を、前回角との相関を考慮した差分観測として使う。
車輪角の積分値を、毎周期独立な絶対方位であるかのように融合しない。
2×2共分散と少数のスカラー計算を使用し、動的メモリ割当は行わない。

正規化残差が大きい間は車輪分散を増やし、正常へ戻れば自動的に通常分散へ戻る。
滑りを断定する検出器ではなく、センサ間の不一致に対する信頼度調整。
一度の不一致で旋回終了まで補正を無効にはしない。

連続推定はstraight補正タスクとは別の高優先度タスクで更新する。
更新とresetを排他し、観測取得中のresetは世代番号で検出して古い観測を捨てる。
カウントresetを通知された区間・取得失敗・物理上限を超える車輪変化は、車輪観測だけ使わない。
その間も有効なジャイロ観測で予測を継続し、正常復帰後は再び車輪を利用する。
MaxPeriodMs（200ms）を超える更新欠落や無効ジャイロを挟む区間は再基準化する。
その区間の動きを復元できないため、実機で周期が維持されることも確認する。

## ログと比較

Nansho3.hのEnableTurnLog=trueにし、BLE端末を接続して起動する。
停止後にKF_h、KF_bias、KF_var、KF_innov、KF_noise、KF_enc_delta、
KF_count、KF_slip、KF_stillを出力する。連続推定タスクから通信は行わない。

- KF_bias: 残留角速度偏り[deg/s]。静止後も大きく変動する場合は校正・静止判定を確認する。
- KF_noise: 車輪の観測分散の倍率。1は通常、大きい値は車輪の信頼度を下げた区間。
- KF_slip: 不一致で分散を増やした回数。実際の滑りが起きた回数とは限らない。
- KF_count: 更新回数。10ms周期ならおよそ毎秒100回。
- KF_still: 静止拘束を使用した回数。

従来のDRIFT_*ではなくKF_*で検証する。
同じ走行を複数回行い、終了位置・方位の平均とばらつきを比較する。
角度が正しくても既に発生した横移動は戻せない。XYずれを長期に抑えるにはライン等の外部観測が必要。

## 右旋回後のずれを確認する追加ログ

Nansho3はEnableTurnLogとEnableStraightLogをtrueにして診断できる（今回の変更で有効）。
BLE端末を接続して起動する。旋回の停止条件・KFの設定値は変更しない。

- `ENC180_*`: turnToHeadingの旋回開始から、左右エンコーダ絶対回転量の平均が180deg以上になった最初の制御周期を保存し、旋回後に出力する。厳密な180degへの補間はしない。`L/R`は符号付き、`AVG`は絶対値の平均。左右片方だけが180degになる条件ではない。
- `IMU_delta`: 旋回開始からの生ジャイロ累積角。`KF_delta`: 同じ旋回開始を基準にした推定角の変化。`KF_h`: 推定絶対方位。
- `WHEEL_delta`: 現在のHeadingFusionSettingsの左右径・トレッドで換算した符号付き車輪角。実際の床に対する角度ではない。
- `BIAS_corr`: 旋回開始からの-bias*dtの累計、`OBS_corr`: 車輪/静止観測でKF角へ加えた更新量の累計。正はCW、負はCCW方向。既に適用された量の記録であり、追加補正しない。
- `ENC180_NOT_REACHED`: 停止までに条件が成立しなかった場合。停止時の値で代用しない。エンコーダ制御旋回ではこの計測は未対応。
- 既存`STOP_*`は停止指令直前の値として残す。`ENC180_*`と比較すれば、その後の回転を確認できる。
- `KF_gyro_sum/KF_bias_sum/KF_obs_sum`: 方位原点reset以降のジャイロ差分・bias補正・観測補正の各累計。`KF_obs`は最新1周期の観測補正。区間の補正量は累計の差を取る。resetをまたいで差分を取らない。
- 直進中は既存の200ms間隔の`PHASE,accel/cruise/decel`制御ログにKFログを追加。TGT、IMU_raw、IMU_h、左右出力と累計の変化を比較する。

センサ値とKF状態は異なる周期で取得されるため、厳密に同時刻の観測ではない。
KF_countは対応するKF更新番号の目安。旋回中の180deg計測は保存のみで通信しないが、
直進中のBLEログ出力は走行時間に影響し得る。実角・横ずれは外部測定が必要。

## 実機での静止bias確認・車輪換算校正（TEST_CASE 21/22）

編集先はapp.hのETROBO_SCENE=6、Scene/Test/Test.hのTEST_CASE。
今回の既定はscene6・case21であり、通常のNansho3走行を開始しない。
ビルドして転送し、通常の開始操作を行い、BLE端末を接続する。

### 21: 静止bias確認

1. 本番と同じ床に機体を置き、手を離して完全静止させる。
2. 接続後2秒待ち、角度原点をresetして15秒間、約250ms間隔でCAL_phase,stillとKFログを出す。モータはブレーキ保持し、走行しない。
3. L/Rが変わらず、ENC_ok=1であることを確認する。KF_stillが増加するかを見る。
4. 後半5秒程度のIMU_deltaの変化を実時間差で割ると残留ジャイロ角速度の目安になる。KF_biasと符号・大きさを比較する。KF_deltaが一方向に流れ続けないかを確認する。
5. KF_stillが0のままなら、静止判定・振動・エンコーダ変化・角速度条件を確認する。閾値を上げる前に原因を調べる。
6. resetでは学習済みbiasを保持する。初回学習から比較する場合は再起動する。真の0度/秒を外部測定した試験ではなく、機体を確実に静止させることが前提。

### 22: 車輪換算校正

1. TEST_CASE=22、TEST_TURN_LEFT=0（右）または1（左）を設定して再ビルドする。
2. 床の基準線に機体の向きを合わせる。左右とも各5回程度、毎回置き直して実施する。
3. 同じ15秒の静止記録後、エンコーダ平均180degを目標に低速で1回旋回する。KF到達角を停止基準にはしない。
4. 直後にブレーキを掛け、2秒後のCAL_phase,turn_settledを記録して終了する。停止遅れ分も含めた最終L/RからWHEEL_deltaを計算する。実際の旋回角は必ず床基準や上方写真で測る。
5. ENC_ok=1、左右が逆符号、AVGが180deg付近であることを確認する。大幅に不足していればタイムアウト・空転などの試行として除外する。
6. IMU_delta、KF_delta、WHEEL_deltaを実測角と比較する。IMUを真値として寸法を決めない。

左右径を固定し、左右旋回に共通の倍率誤差がある場合の有効トレッド修正目安:

```text
新しいEffectiveTrackMm = 現在値 × |WHEEL_delta| / |外部実測の旋回角|
例: 計算90度、実測85度、現在112mm → 約118.6mm
```

複数回・左右両方向の比を比較してから設定する。左右で倍率が異なる場合やばらつきが大きい場合は、
単一トレッドでは説明できない。接地・滑り・左右径差を追加確認する。
この旋回試験だけでは左右径とトレッドをそれぞれ一意に決められないため、まず左右径を固定して評価する。
補正値の自動書換えは行わない。

検証終了後はapp.hのETROBO_SCENEを元の4へ戻して通常のNansho3走行と比較する。
CAL_msとturnToHeadingのSTOP_msはget_timによる実時間。ログ通信の所要時間も実時間へ含む。

## 静止判定の微小エンコーダ揺れ対策

毎周期の差分0という条件を廃止し、停止確認開始からの左右それぞれの最大値−最小値を調べる。
今回の初期値は2deg。0→1→0の揺れは許容し、各周期が小さくても回転が累積して幅を超えれば確認をやり直す。
固定長の移動窓ではなく、条件が途切れるまで同じ確認区間を継続する保守的な判定。
モータへの停止指令も必須で、駆動指令中は適用しない。停止指令は実際の静止を保証しないため、IMU・車輪・角速度条件も同時に用いる。
欠測・カウントreset・時刻飛びでも確認時間をリセットする。
成立後は車輪の微小揺れを観測せず、既知角度増分0を使用する。gyro観測を二重適用しない。

追加ログ:

| 項目 | 意味 |
|---|---|
| ST_imu | IMUの静止判定（1=静止） |
| ST_cmd | モータへ停止指令中なら1。最後の非ゼロ出力ログとは別 |
| ST_enc | 有効な車輪差分を取得できた場合1 |
| ST_rate | ジャイロ角速度[deg/s] |
| ST_sec | 現在の静止条件の連続成立時間[s] |
| ST_Lrange / ST_Rrange | 停止確認区間の左右車輪変動幅[deg] |
| ST_reject | 0=条件成立中。1=駆動指令、2=IMU非静止、4=車輪観測無効、8=角速度超過、16=車輪変動幅超過。複数は加算 |

ST_reject=0でもST_secが0.5秒未満なら確認中で、まだKF_stillは増えない。
ST_imu=0が続く場合、車輪許容幅を広げても解決しない。
TEST_CASE=21を再実行し、KF_still増加・KF_biasの収束・KF_hの安定を確認してから旋回校正へ進む。

### ブレーキ保持時のIMU静止判定

ST_imuはpbdrv_imu_is_stationaryによるセンサ単体の判定を使用する。
hub_imu_is_stationaryはセンサ静止に加え、全モータがcoastであることも要求するため、
ブレーキ保持する本診断ではfalseになる。この上位APIをKF静止拘束の条件に使わない。
モータ停止指令・車輪変動幅・角速度の独立条件は維持し、センサ取得失敗時は静止と認めない。
IMUドライバ自身の校正条件は変更せず、KFはドライバ校正後の残留biasを推定する。

## 旋回誤差をbiasへ持ち越さない修正

走行中の車輪差分観測では角度だけを更新し、biasゲインを0とする。
biasとその分散は車輪観測で更新せず、角度とbiasの交差共分散は部分更新に合わせて更新する。
予測時のbias分散の増加は維持し、次の静止時の変化への追従を妨げない。
静止拘束が成立すると従来どおり角度とbiasを更新する。

- `KF_bias_learn=1`: 静止確認済みでbias学習中。0: bias値を維持。
- 右旋回・左旋回の繰返しでも、走行中KF_biasが変化しないことを確認する。
- `KF_bias_sum`は固定biasを毎周期適用した累計なので、走行中も増減する。biasの再学習ではない。
- 車輪観測による`OBS_corr`は走行中も更新する。倍率誤差を解決する処理ではない。
- 起動後、機体を静止させて学習してから走行する。未校正で出発すると、その間の誤差は残る。resetは学習値を保持する。
- 後から静止しても、過去の走行位置や方位を外部基準へ戻すことは保証しない。

回帰試験では真bias既知の静止校正後、ジャイロ83度/車輪90度の不一致を持つ左右旋回を各30回与えても
biasが固定されること、および次の静止で変化したbiasを再学習することを確認する。

## 四角走行での右ずれ・左ずれ切り分け

ETROBO_SCENE=6、TEST_CASE=17、TEST_TURN_LEFT=0を使用する。
開始後BLE接続→角度原点reset（bias保持）→四角走行の順。Test17の開始時の2秒待機・15秒静止診断は削除済み。静止診断を行う場合はTEST_CASE=21を使用する。
試験側の早期停止3+(-1)deg設定は削除済み。旋回後待機は80msで、以前の前待ち200msを後待ちへも足す処理を削除した。
通常Nansho3と旋回出力80・低速40・減速開始30deg・早期停止0・coast・後待ち80msを合わせた。
直進距離・直進制御など四角走行自体の条件はNansho3と同一とは限らない。

A/Bは新しい同一コードで、床・開始位置・速度・左右旋回方向・周回数・ログ有効状態をそろえて行う。
以前のログは旋回終了条件が異なるため、そのままA/Bの基準にしない。

1. A: HeadingFusionSettings.hのMovingWheelObservation=trueで同じ周回数を走行し、各周回の終了位置と向きを外部測定する。
2. B: MovingWheelObservation=falseにだけ変更して再ビルド・転送し、同じ試験を繰り返す。
3. falseでも静止bias学習と固定bias補正は有効。停止指令・車輪変動幅等の静止確認も有効。旧TurnDriftは使わない。
4. falseにするのはKFの走行中車輪角度観測だけ。旋回モータ左右差補正・直進方位PI・停止方法は維持する。
5. Bで再現性をもって改善するなら走行中の車輪観測が関与する。A/Bで同じなら1D角の倍率/軸・旋回中心移動・接地・停止動作等を調べる。単独の一試行では断定しない。

SQUARE_CONFIGで試験条件を確認する。SQUARE_DRIVEは各直進ログの目標・raw/KF角・方位誤差・最後の非ゼロ左右出力。
LAST_L/Rは停止後も最後の非ゼロ指令を保持するため、停止中の実出力ではない。ST_cmdで停止指令を確認する。
続くKFログのKF_biasは走行中固定、KF_bias_learnは0であることを確認する。
Bでは静止時のOBS_corrだけが残るため、走行区間のKF_obs_sum差分は0になる。
ログ通信は時間に影響し得るため、両試験で同じ設定にする。

## 旋回中の累積角度差ゲイン（現方式）

HeadingFusionSettings.hのTurnCorrectionGain=0.2を使用する。
turnToHeading/turnByEncoderの開始時に累積比較区間を開始し、関数終了時に終了する。
この区間中は従来の毎周期の車輪KF角度観測を停止し、次の固定ゲイン補償へ置き換える。

```text
目標補正量 = TurnCorrectionGain × (累積車輪旋回角 − 累積ジャイロ角)
今回加える量 = 目標補正量 − この旋回で既に適用した補正量
```

同じ10ms更新で得た車輪・ジャイロ差分を積算するため、比較開始と終端の時間基準をそろえる。
角度差10degならgain0.2で2deg、0.5で5deg。0なら旋回中の車輪角補償なし。
設定可能範囲は0〜1。符号付きで左右対称に扱う。既に適用した分を毎周期繰り返し加算しない。
旋回終了後も適用済みの方位補正は保持し、直進の共通方位へ引き継ぐ。
走行中biasを学習しない処理は維持する。旋回中も固定biasは別途適用する。

TURN_gyro/ TURN_wheelは同じ有効観測区間の累積角、TURN_corrは適用済み累積補正量。
TURN_activeが0でも直前旋回の結果を保持し、次の旋回開始または原点resetでクリアする。
車輪欠測区間は両累積とも除外し、補正値を保持してジャイロ予測のみ継続する。
旋回関数終了後の惰性区間はこの補償区間に含めない。追い旋回・新たな待機は追加しない。

MovingWheelObservationは旋回区間外の従来の車輪観測の比較用設定。
旋回補償の有無を比較する場合はTurnCorrectionGain=0/0.2を使用する。
KF分散はこの固定ゲイン補償の校正精度を含まない。車輪寸法誤差や滑りを真値として補償する危険は残る。
共通方位を使用するため旋回終了判断にも推定角の変更は反映されるが、停止条件自体は変更しない。
