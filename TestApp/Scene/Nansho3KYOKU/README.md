# Nansho3KYOKU

ゲートの格子座標と1マスの距離から曲線経路を自動生成し、Pure Pursuitで追従する。
格子は位置の指定にだけ使い、走行経路を上下左右の移動に制限しない。
赤→青→黄→次周の赤を接続し、ラリー中の停止・その場旋回をなくす。
既定はHub向けの軽量モード。通過方向を簡易評価した順に試し、最初の成立経路を採用する。
全候補を比較するモードも残し、こちらではカーブの減速・加減速を含む推定走行時間で選ぶ。

## 起動

`app.h` の `ETROBO_SCENE` を **7** にして、通常どおりTestAppをビルド・転送する。
既定のシーン4と、既存Nansho3の通し走行は変更していない。
Dポートのフォースセンサを押して離すと、既存Nansho3の初期動作を実行する。

```text
低速LT → 白検知・ジャイロreset → バック → 旋回 → 進入直進・停止
    → 全経路計算 → 曲線追従（周回中は停止しない）→ Finish付近で停止
```

初期動作は `Nansho3.h` の `Initial*` を共用する。
進入完了後に経路を計算するため、この位置で計算待ちが発生する。
計画の計算時間は推定走行時間に含まない。同じ姿勢間の探索結果は周回・候補間で再利用する。
計算中は定期的に他タスクへ実行を譲り、`PlanTimeoutMs`（既定10秒）で打ち切る。
超過するとQを表示し、部分的な経路では走行しない。Hub上での計算時間は実測が必要。
既存の黒線・青検知による退出処理は呼ばず、指定したFinishで終了する。

## 座標の指定

調整値は **Settings.h** にまとめている。変更後は再ビルドする。
距離:mm、速度:mm/s、加速度:mm/s²、角度:rad、時間:ms。

| 設定 | 意味 |
|---|---|
| `GridStepXMm` / `GridStepYMm` | x/y方向それぞれの1マスの実測距離 |
| `GridStart` | 初期動作の直進完了地点の格子座標 |
| `GridGates` | 赤・青・黄の順に、開口を横切る2点を指定 |
| `GridFinish` / `FinishHeadingRad` | 終了位置の格子座標と向き |
| `CourseMin*Mm` / `CourseMax*Mm` | Start基準の走行可能範囲 |
| `RallyLapCount` | 周回数。初回調整は1周から始める |

例えば既存Nansho3の `GateSeg red = {{3}, {2, 3}}` に対応する指定は、
次のとおり。`a` と `b` は支柱の位置ではなく、ゲートを横切る経路上の2点。

```cpp
constexpr GridGate GridGates[3] = {
  {{3.0f, 2.0f}, {3.0f, 3.0f}},  // 赤
  {{0.0f, 4.0f}, {1.0f, 4.0f}},  // 青
  {{4.0f, 0.0f}, {4.0f, 1.0f}},  // 黄
};
```

開口中央は2点の中点、通過軸はa→bで決める。各ゲートの両向きを探索するため、
a/bの順序で通過方向を固定するわけではない。同一点や斜めの2点は不正として扱う。
2点の間隔はゲート幅ではない。開口幅は `GateInnerWidthMm` に別途指定する。

格子座標から実距離への変換は次の式。

```text
x[mm] = (格子x - GridStart.x) × GridStepXMm
y[mm] = (格子y - GridStart.y) × GridStepYMm × (Lなら+1、Rなら-1)
```

Startは車軸中央の(0,0)、進入完了時の前方が+x、左が+y。
既存の `ETROBO_COURSE_L` は **0=L / 1=R**。Rでは格子のy方向と終了方位を反転する。
`CourseMinYMm` / `CourseMaxYMm` も反転する。L/Rの配置自体が異なる場合は、
コースを切り替えるときにGridGatesもその配置へ書き換える。
格子座標は既存Nansho3から自動取得せず、このヘッダで指定する。

コース範囲は格子番号ではなく、Start基準の実距離で指定する。
車体の四隅・余裕幅を含めて範囲内に収まる必要がある。
現在の配置・1マス250mm・車体寸法・境界は**数値試験用の仮設定**。
上の記述例も含め、実配置で経路が成立するかは寸法と合わせて確認する。

## 経路生成と追従

1. ゲート前後に、車体長・先読み距離を考慮した直線区間を設ける。
2. ゲート間を、始点と終点の向きをそろえた3次ベジェ曲線でつなぐ。
   直接つながらない場合だけ、中間位置・向きの有限候補を探索する。
3. 車体を向き付き矩形、脚・足元を円として、境界・接触・順番外の通過を調べる。
4. 曲率、左右車輪の速度上限、横加速度から各点の速度上限を決める。
   後ろ向きの減速計算と前向きの加速計算を行い、始点・終点だけ速度0にする。
5. 軽量モードでは、距離と向きの変化を使って通過方向8組の優先順を決める。
   直接接続を全方向で先に試し、最初に成立した全周回の経路を採用する。
   直接接続できない場合だけ9位置×4方向の迂回候補を試し、最初の成立接続を使う。
   全候補比較モードでは25位置×8方向の迂回探索と曲線形状の比較を行う。
6. 左右エンコーダの移動量とジャイロからXY位置・向きを更新し、Pure Pursuitで追従する。
   左右の速度指令はPI＋フィードフォワードでモータパワーに変換する。

推定時間は、隣接点の距離dsと速度v0/v1から `2×ds / (v0+v1)` を積算する。
`Path::estimatedTime()` で取得できる。滑り、モータ応答、追従補正による時間差は含まない。
全候補比較モードの接続区間には局所的な速度上限による近似時間を使い、全候補の比較では
全経路の加減速を反映する。大域的な最短距離・最短時間を保証する探索ではない。

## 計算時間の設定

`FastPlan=true` がHub向けの既定値。曲線形状や全経路の最適化を続けず、
成立経路が見つかった時点で速度計画を1回だけ行う。採用後の経路再生成も省略する。
接触判定・順番外ゲートの横断禁止・最小旋回半径・追従処理は維持する。
直接接続で成立した場合は、重い迂回探索を実行しない。

`FastPlan=false` にすると従来の全候補比較へ戻る。
`CurveStyleCount` と `OptimizeTravelTime` は全候補比較時の設定で、
軽量モードでは曲線倍率1、最初の成立候補を使うため変更不要。
軽量モードは最短時間を保証せず、候補を絞るため従来モードで成立する配置でも
Eになる場合がある。実コースに対する計算時間と走行時間は実測で確認する。
どちらのモードでも `PlanTimeoutMs` の打ち切りと同一区間の結果再利用を行う。

## 調整の順序

1. **位置と寸法を合わせる。** GridStart、1マスの距離、ゲート座標、終了位置、
   コース範囲、車体の前後長・幅・高さ、ゲート内寸・脚の張り出しを実測して設定する。
   進入動作が毎回同じ位置・向きで終わるよう、Nansho3側のInitial設定も調整する。
2. **距離と方位を合わせる。** `WheelDiameterMm` は既知距離の直進で校正する。
   左右エンコーダは前進で正になるよう `LeftEncoderSign` / `RightEncoderSign` を設定する。
   `WheelTrackMm` は左右車輪の接地中心間距離。旋回の実測とも照合する。
3. **低速・1周で速度制御を合わせる。** `RallyLapCount=1` にし、Cruise/Gate速度を下げる。
   まず `SpeedFeedForward` と `StaticFrictionPower`、次に `SpeedKp`、最後に `SpeedKi` を調整する。
   MinRunPowerが高すぎると低速で加速・惰走を繰り返すため、実機の動き出す出力と照合する。
4. **追従を合わせる。** 蛇行する場合は先読み距離を少し増やす。
   カーブの内側へ切り込む場合は先読みを減らすか速度を下げる。
   先読みを大きくするとゲート前後の直線も長くなるため、経路を再確認する。
5. **速度を上げる。** Cruise/Gate速度、左右車輪の上限速度、加速度、横加速度を
   1項目ずつ上げる。周回数を増やし、最後のゲートでも位置誤差が余裕幅内か確認する。

| 調整値 | 効果・注意 |
|---|---|
| `CruiseSpeedMmPerSec` | 接続区間の速度上限。別の制約が低いと上げても速くならない |
| `GateSpeedMmPerSec` | ゲート前後の直線区間の速度上限 |
| `MaxWheelSpeedMmPerSec` | 片輪の速度上限。カーブでは外輪で制限される |
| `AccelerationMmPerSec2` | 経路上の加減速と、制御周期ごとの左右目標速度の変化上限 |
| `LateralAccelMmPerSec2` | カーブ速度の上限。上げすぎると滑りやすい |
| `MinTurnRadiusMm` | 許容する最小半径。トレッドの半分より大きくする |
| `PathSampleMm` | 曲線の点間隔。小さくすると計算時間と点数が増える |
| `FastPlan` | 既定true。最初の成立経路で計算を終了するHub向け設定 |
| `CurveStyleCount` | FastPlan=false時のみ有効。既定1、2〜3で比較候補が増える |
| `OptimizeTravelTime` | FastPlan=false時のみ有効。trueで時間優先、falseで距離優先 |
| `LookaheadMinMm` / `LookaheadMaxMm` / `LookaheadTimeSec` | 先読み距離を速度に応じて変更する |
| `CollisionMarginMm` | 寸法誤差と追従ずれに対する余裕 |
| `MaxTrackingErrorMm` | 推定位置と経路の許容ずれ。CollisionMargin以下にする |

正の追従パワーは `MinRunPower`〜`MaxPower`、速度超過で出力不要なら0。
パワー0は惰走・減速の指令で、経路途中で停止・旋回する計画は作らない。
初期LTや進入動作にはこの出力下限を適用しない。

Pのまま待つ場合は、転送したバイナリが最新版か確認する。
最新版では計算が継続していれば10秒でQになる。Qなら `FastPlan=true` になっているか確認する。
10秒を大きく過ぎてもPのままの場合は、通常の計算待ち以外の可能性があるため、
初期動作後からの待ち時間とHubの応答状態を確認する。

## 停止表示

| Hub表示 | 状態・確認箇所 |
|---|---|
| P / R / D | 経路計算中 / 追従中 / 完了 |
| Q | 経路計算の時間上限超過。FastPlan=trueを確認。必要ならPlanTimeoutMsを調整 |
| E | 経路不成立。配置、寸法、境界、最小半径、点数上限を確認 |
| F | 追従不成立。距離校正、初期姿勢、先読み、速度を確認 |
| C | 接触を予測してブレーキ停止。停止後にC→詳細番号を3回表示 |
| C→1 | コース境界。CourseMin/Max、推定位置、車体寸法を確認 |
| C→2 / 3 / 4 | 赤 / 青 / 黄ゲートの脚。ゲート座標、開口幅、脚、追従ずれを確認 |
| C→5 | 計算値が不正。速度・姿勢・予測周期を確認 |
| G / N | ジャイロ / エンコーダの1周期の変化量が上限超過 |
| T | 制御周期異常 |
| S | 指令を出しても移動しない。出力・配線・接触を確認 |
| X | RunTimeoutMs超過 |

## 検証

workspace/TestAppで実行する。

```sh
g++ -std=c++11 -O2 -Wall -Wextra -Werror -IScene/Nansho3KYOKU \
  tests/nansho3_kyoku_test.cpp Scene/Nansho3KYOKU/Path.cpp -o /tmp/kyoku-test
/tmp/kyoku-test /tmp/kyoku-path.csv
```

仮配置のL/R各6周、観測できている初期位置ずれからの追従、18回のゲート通過順、
非接触、途中の左右速度が正であること、速度上限、加減速、異常入力を確認する。
実機と同じ200msの等速円弧予測も各周期で確認し、境界・各色ゲート・不正値の判定を検証する。
距離優先では短いが遅い経路になる配置で、時間優先が速い候補を選ぶことも確認する。
計算中断、部分経路の無効化、中断後の再計画も確認する。
CSVは `x,y,yaw,curvature,s,speed`。XYを等縮尺で描画し、sに対するspeedで減速箇所を確認する。

## 制約

- 実機走行は未検証。試験モデルは理想的な車輪速度を使用し、滑りやIMUドリフトを再現しない。
- 初期位置は既知とみなす。ライン・カメラによる位置補正はなく、観測できない累積誤差は修正できない。
- ゲート中央を垂直に通過し、各色の通過方向は全周回で共通。全ての配置で経路が見つかる保証はない。
- 接続部の接線は一致するが、曲率連続は保証しない。左右速度の変化制限で急変を抑える。
- 経路は最大4096点、約96KiB。超過時は不成立。タスクのローカル変数には置かない。
- 初期動作の接触判定は含めない。接触判定は設定形状と推定姿勢に対するもの。
- 仮配置の6周は推定約124秒（設定・モードで変動）。競技全体の時間に合わせ、周回数・速度・配置を調整する。
