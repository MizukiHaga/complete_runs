# Nansho3KYOKU

既存 Nansho3 から独立した、全経路事前生成 + Pure Pursuit の単体走行シーン。
`app.h` の `ETROBO_SCENE=18` で選択する。既存の既定値4と通し走行は変更していない。

## 調整用ヘッダ

`Settings.h`に実機の調整値を単位・用途別にまとめている。
`Nansho3KYOKU.h`からも読み込む。変更後は再ビルドして転送する。

| 調整内容 | 定数 |
|---|---|
| 追従中の最低・最大パワー | `MinRunPower=35` / `MaxPower=70` |
| 速度制御 | `SpeedKp` / `SpeedKi` / `SpeedFeedForward` / `StaticFrictionPower` |
| 直線・ゲート通過速度 | `CruiseSpeedMmPerSec` / `GateSpeedMmPerSec` |
| 先読み距離 | `LookaheadMinMm` / `LookaheadMaxMm` / `LookaheadTimeSec` |
| 車体寸法・車輪径・トレッド | `Body*` / `WheelDiameterMm` / `WheelTrackMm` |
| ゲートの内寸・脚・余裕幅 | `GateInner*` / `GateFootRadiusMm` / `CollisionMarginMm` |
| 経路・周回 | `Start` / `Gates` / `Finish` / `RallyLapCount` |
| 制御・停止判定 | `ControlPeriodMs` / `StallTimeoutMs` / `MaxTrackingErrorMm`ほか |

最低パワー35はPure Pursuitの速度制御に適用する。
初期LT（現在30）・バック・旋回・進入直進は、既存`Nansho3.h`の`Initial*`を共用する。
経路探索の候補数や計算上限は`Path.h`にまとめている。

実行処理は`runInitialApproach()`、`planRallyPath()`、`followRallyPath()`、
`finishRun()`へ分け、停止理由は`StopReason`で管理する。

## 開始地点と設定

起動時は既存 Nansho3 単体起動と同じ低速LT開始地点に設置する。
Nansho3 の `testInitialTrace()` と `initialRun(false)` を再利用し、
**低速LT→白検知・ジャイロreset→バック→旋回→直進・減速停止**を行う。
進入の距離・速度・旋回補正は既存 Nansho3 と共通で、L/Rは `ETROBO_COURSE_L` に従う。
現在の設定ではLTパワー30、バック140°、Rは+90°/Lは-90°旋回、直進630°。

`Settings.h` の `Start` は、この進入直進が完了した後の車軸中央の位置 [mm] と向き [rad]。
現在は **(0,0)、+x向き**。LT開始地点を(0,0)とするわけではない。
進入後に `InitialSettleMs`（初期値200ms）待ち、現在のジャイロ方位とエンコーダ値を
Pure Pursuitの基準として取得する。進入中の移動量を経路追従のオドメトリに加算しない。
`Finish` で指定した位置付近で停止する。既存の黒線・青検知による退出処理も呼ばない。
進入完了時の方位を基準にジャイロのCW正をCCW正へ変換する。世界座標の+yは進入完了時の左側。

ゲートは赤・青・黄の順で、開口中央 `center` と通過方向 `normal` を指定する。
`normal=0` の場合、ゲートの開口を+x/-x方向に通過し、脚は中央の±y側にある。
ゲート中心は車体中心の通過点であり、脚の座標ではない。
現在の開始・終了・ゲート座標・境界は動作確認用の仮配置。
**旧 Nansho3 の仮想格子や GateSeg の値から実配置を自動推定していない。**
経路側のL/Rは実際の配置を世界座標へ変換して設定する（ゲート座標はETROBO_COURSE_Lによる自動反転なし）。

車輪径、トレッド、車体の前後長・幅・高さ、足元を含む脚の半径、コース境界、
エンコーダ符号、速度制御ゲインを実測値で設定する。
ゲート内寸の初期値は幅240mm、高さ245mm。足元半径25mmと車体寸法は仮定値。
シーン18では従来のapp.cppと同じDポートのフォースセンサを押して離すと、
低速LTから初期動作を開始する。Hub中央ボタンは開始トリガーではない。
進入完了後、停止したまま全経路を計算し、成功すればPure Pursuitを開始する。
Hub表示はP=経路計算中、E=経路不成立（低い音）、R=追従中。
停止後の表示はD=完了、S=停滞、F=追従指令不成立、C=接触予測、
G=方位急変、N=エンコーダ急変、T=制御周期異常、X=180秒超過。
寸法確認フラグによる起動停止は設けない。経路不成立の場合は進入完了位置で停止する。
走行開始前・制御中のシリアル出力は行わず、未接続コンソールによる待ちを避ける。

## 処理

- 従来と同じ開始条件で、既存Nansho3と同じ初期動作でStartへ進入。
- 停止してStart→赤→青→黄→次周赤…→終了の全経路を生成。
- 基準姿勢を設定し、全経路の生成完了後に追従を開始。
- ゲート前後に車体長・先読み距離を考慮した直線を確保し、間を3次ベジェで接続。
- 各色の通過方向8組を比較。直接接続が不成立なら中間姿勢候補を探索。
- 車体を向き付き矩形、脚・足元を円として、余裕を加えた接触判定を実施。
  障害物間のサンプリングには移動・回転の余裕も加える。
- 接続経路で順番外のゲート開口を横切る候補を除外。
- 曲率・車輪速度上限・加減速から速度列を作り、終点以外は速度を0にしない。
- エンコーダの符号付き移動量とジャイロによるオドメトリ、可変先読みPure Pursuit。
- 左右の目標速度にエンコーダ速度PI + フィードフォワードでパワー指令。
  `MinRunPower=35`、`MaxPower=70`で正の出力範囲を制限する。
  停止指令や速度超過で出力不要のときは0。
  `StaticFrictionPower`（初期値18）で低速の静止摩擦を補償する。
  補償は0〜30mm/sで滑らかに増やし、速度0の指令はパワー0とする。
  既存の直進方位補正は走行中無効にし、終了時に戻す。
- 追従ずれ、障害物への短時間予測接近、エンコーダ/方位急変、停滞、時間超過で停止。

## 検証

workspace/TestApp で以下を実行する。

```sh
g++ -std=c++11 -O2 -Wall -Wextra -Werror -IScene/Nansho3KYOKU \
  tests/nansho3_kyoku_test.cpp Scene/Nansho3KYOKU/Path.cpp -o /tmp/kyoku-test
/tmp/kyoku-test /tmp/kyoku-path.csv
```

仮配置と鏡像の各6周で追従完了・接触なし・赤青黄18回の順序を検証する。
不正寸法、経路逸脱時の停止、オドメトリ、角度の±π跨ぎも確認する。
CSVはx,y,yaw,curvature,s,speedを出力する。

## 現段階の制約

有限候補の中で短い経路を選ぶ方式で、距離・時間の大域的最適解は保証しない。
周回中の各色の通過方向は固定。見つからない配置は走行前に停止する。
接続部は接線方向を合わせるが曲率連続は保証しない。
経路データは最大4096点（約96KiB）。超過する経路は不成立。

実機未検証。試験は理想的な左右速度追従のシミュレーションであり、滑り、
IMUドリフト、速度制御の機械差、ゲート設置誤差は再現していない。
進入完了位置をStartとみなすため、初期動作自体の位置ずれは自動補正されない。
進入動作は既存Nansho3と共通で、今回の曲線経路の接触判定には含まれない。
外部観測による自己位置補正は未実装で、余裕幅を超える累積誤差には別途対策が必要。
接触回避判定は設定形状と推定姿勢に対するもので、実機の非接触を保証するものではない。
